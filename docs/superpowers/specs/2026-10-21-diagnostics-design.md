# 第 5d-3 期：日志与诊断信息导出 设计

日期：2026-10-21。状态：设计已确认。前置：`2026-10-21-layout-backup-design.md`（数据页）。

## 1. 目标

应用记录运行日志；设置「数据」页可把日志、崩溃报告、设置、布局与系统信息打包导出，便于排查卡顿、导入失败等问题。

## 2. 参考依据

LaunchOS「诊断」：日志导出、崩溃日志、「日志文件打包失败」「无日志文件」。2026-10-20 的卡顿排查只能靠采样与系统日志，应用自身没有任何记录。

## 3. 交互规则

### 3.1 日志

- 写到 `~/Library/Logs/Launch/launch.log`，超过 1MB 时改名为 `launch.1.log`（覆盖旧的），最多保留两份；同时写入系统日志（子系统 `dev.yocn.launch`）。
- 每行：时间（精确到毫秒）、级别（信息 / 警告 / 错误）、内容。
- 记录：启动（应用与系统版本）；扫描到的应用数与耗时；布局读取、保存、导入的失败；读单个图标超过 1 秒；唤起时主线程耗时超过 0.3 秒。
- 不记录搜索内容与启动了哪些应用。

### 3.2 导出诊断信息

- 数据页「诊断」：「导出诊断信息…」，保存对话框默认文件名「Launch 诊断 2026-10-21.zip」，结果显示在下方。
- 压缩包内：日志文件、本应用的崩溃报告（`~/Library/Logs/DiagnosticReports` 中以 LaunchApp 开头的）、设置（导出的偏好设置）、布局文件、`系统信息.txt`（应用版本、macOS 版本、各屏幕尺寸与缩放、应用数、来源目录）。
- 只保存到所选位置，不上传。打包失败时提示原因。

## 4. 组件

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `AppLog` | LaunchApp（新增） | 写日志文件与系统日志、按大小轮换；串行队列写入 |
| `DiagnosticsExporter` | LaunchApp（新增） | 收集文件到临时目录、写系统信息、用 ditto 打包 |
| `CatalogWatcher` / `LayoutCoordinator` / `ApplicationIconResolver` / `LauncherController` | 扩展 | 在上述时点记日志 |
| `SettingsView` / `LaunchApp` | 扩展 | 数据页「诊断」与保存对话框 |

## 5. 测试与验证

- `AppLog`：行格式、追加、超过上限轮换且只保留一份旧文件。
- `DiagnosticsExporter`：临时目录中的日志、崩溃报告、设置、布局与系统信息都进压缩包（解压核对文件名与内容）；缺少的来源跳过不报错。
- 目标机 e2e：启动后日志里有启动与扫描记录；数据页导出到临时目录，解压后文件齐全；删除临时目录。只跑本期 e2e。
