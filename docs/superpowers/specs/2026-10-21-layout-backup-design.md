# 第 5d-1 期：布局备份导出与导入 设计

日期：2026-10-21。状态：设计已确认。前置：`2026-10-19-layout-inheritance-design.md`（布局存储与备份互换）。

## 1. 目标

设置窗口新增「数据」页：导出布局备份、从备份导入；「从 Launchpad 导入布局…」「恢复导入前的布局」也放进这一页。布局文件与备份文件改为键排序、带缩进的格式。

### 不在本期

应用来源目录、诊断日志、清除缓存（后续 5d 各期）；备份里带设置。

## 2. 参考依据

LaunchOS「布局数据备份」：导出备份（选择文件夹）、导入备份（选择文件，确认「替换当前布局？现有应用排列和文件夹将被覆盖」）、「不支持的备份版本」「读取备份文件失败」「已成功导入 N 个应用、N 个文件夹和 N 个页面」。

## 3. 交互规则

### 3.1 数据页

- 「布局备份」：「导出布局…」「导入布局…」，下方显示最近一次结果（「已导出到 …」「已导入：N 页、N 个文件夹、N 个应用」）。
- 「Launchpad」：「从 Launchpad 导入布局…」（读不到 Launchpad 数据时置灰）、「恢复导入前的布局」（没有备份时置灰）。菜单栏原有两项保留。

### 3.2 导出

- 保存对话框，默认文件名「Launch 布局 2026-10-21.json」，可改名与位置。
- 内容：页面、文件夹、隐藏的应用，与布局文件同一格式。

### 3.3 导入

- 打开对话框，只能选 JSON 文件。
- 读取失败或版本不支持：提示原因，布局不变。
- 确认框：「从备份导入布局？」列出备份的页数、文件夹数、应用数、本机已安装数；未安装的保留位置，重新安装后回到原处；本机有而备份里没有的应用排在最后；会覆盖当前布局，覆盖前自动备份。
- 确认后替换：当前布局存为备份，可用「恢复导入前的布局」换回；撤销记录清空；备份里的隐藏应用一并恢复。

### 3.4 文件格式

布局文件与导出的备份都按固定键顺序、带缩进、不转义斜杠写出：同样的布局每次写出的字节相同，可直接阅读与对比。读取兼容旧的紧凑格式。

## 4. 组件

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `LayoutBackup` | LaunchCore（新增） | 编码（键排序、缩进）、解码与版本校验、由备份生成导入结果与摘要 |
| `LayoutStore` | 扩展 | 读写改用 `LayoutBackup` |
| `LayoutCoordinator` | 扩展 | 导出当前布局；导入备份（确认、替换、发布） |
| `LayoutPrompting` / `AlertLayoutPrompter` | 扩展 | 备份导入确认；摘要文字可指定来源 |
| `SettingsView` | 扩展 | 「数据」页 |
| `LaunchApp` | 扩展 | 保存与打开对话框、读写文件、结果文字 |

## 5. 测试与验证

- `LayoutBackup`：编码稳定且键有序、带缩进；解码拒绝不支持的版本与无效内容；摘要计数（页、文件夹、应用、已安装、新应用）；导入保留隐藏应用。
- `LayoutStore`：保存后为新格式，旧紧凑格式可读。
- `LayoutCoordinator`：导出内容与当前布局一致；导入确认后替换、可恢复、撤销记录清空；取消不变；无效文件提示且不变。
- 目标机 e2e：数据页导出到临时目录，文件内容与布局一致；改动布局后从该文件导入，确认后布局恢复为导出时的样子；「恢复导入前的布局」换回；导出的临时文件删除。回归各期 e2e。备份并还原布局与设置。
